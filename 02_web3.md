# 02 — Web3 & DeFi

## Web1 → Web2 → Web3

| Era | Characteristic | Who controls data |
|---|---|---|
| Web1 (1990s) | Read-only, static HTML | Server owners |
| Web2 (2000s-now) | Read-write, social, apps | Platforms (Google, Meta, AWS) |
| Web3 (2015-now) | Read-write-own, decentralized | Users (via private keys) |

Web3 core idea: **you own your data and assets via cryptographic keys**, not platform accounts. No company can freeze your wallet or delete your assets.

Practical reality: Web3 infra is still immature. Most "Web3 apps" use centralized front-ends, centralized data indexers (The Graph), and rely on Infura/Alchemy as RPC endpoints.

## Smart Contracts

Programs that run on a blockchain. Code is public, execution is deterministic, output is immutable.

```solidity
// Simplest possible smart contract
contract SimpleStorage {
    uint256 public value;
    
    function set(uint256 _value) public {
        value = _value;
    }
    
    function get() public view returns (uint256) {
        return value;
    }
}
```

Once deployed, this code runs exactly as written. No one can change it (unless it has an upgrade mechanism built in). Every call costs gas.

### Why This Matters for Quant

Smart contracts = programmable money. You can encode:
- Lending protocols (Aave: deposit ETH, borrow USDC)
- Trading logic (Uniswap: swap tokens atomically)
- Derivatives (dYdX: trade perpetuals on-chain)
- Arbitrage (flash loans: borrow → use → repay, all in one transaction)

## Automated Market Makers (AMM)

AMMs replace order books with **liquidity pools**. A pool holds two (or more) tokens. Trades happen against the pool, not against another user.

### Uniswap v2: Constant Product Formula

```
x * y = k
```

Where:
- `x` = reserve of token A
- `y` = reserve of token B  
- `k` = constant (invariant)

When you trade token A for token B, you add A to the pool and remove B, keeping `k` constant.

**Example**:
```
Pool: 100 ETH, 200,000 USDC → k = 20,000,000
You buy 1 ETH:
  New ETH reserve: x' such that x' * y' = k
  x' = 99 ETH (you removed 1)
  y' = k / x' = 20,000,000 / 99 = 202,020 USDC
  You pay: 202,020 - 200,000 = 2,020 USDC for 1 ETH
  Implied price: $2,020 (vs $2,000 before trade)
  Price impact: 1% for 1 ETH in a 100 ETH pool
```

**Key insight**: large trades relative to pool size = high slippage. Pool depth (TVL) determines transaction cost.

### AMM Variants

| Protocol | Formula | Best for |
|---|---|---|
| Uniswap v2 | x*y=k | General pairs |
| Uniswap v3 | Concentrated liquidity | Capital efficiency |
| Curve | StableSwap | Stablecoin-to-stablecoin |
| Balancer | Weighted pools | Multi-asset baskets |

### Curve StableSwap Formula

For stablecoins (expected to maintain peg), standard x*y=k gives too much slippage. Curve uses a hybrid:

```
A * (x + y) + D = A * D + D³ / (4xy)
```

Where `A` is amplification factor. At peg, behaves like constant sum (`x+y=k`, zero slippage). Far from peg, falls back to constant product (prevents pool drain).

This is why Curve dominates stablecoin and wrapped-asset swaps.

### Uniswap v3: Concentrated Liquidity

Liquidity providers (LPs) choose a price range `[lower, upper]` instead of providing liquidity across all prices. More capital efficiency, but requires active management.

```
Effective capital: $10,000 in range [1800, 2200] ≈ $100,000 in v2
```

**Impermanent Loss**: if price moves out of your range, you stop earning fees. If it moves far out, you hold 100% of the worse asset.

## Liquidity Pools and LP Tokens

When you provide liquidity to an AMM:
1. You deposit both tokens in ratio matching current pool price
2. You receive **LP tokens** representing your share
3. LP tokens earn a portion of all trading fees
4. Redeem LP tokens → get back your share (with fees earned)

**Impermanent Loss (IL)**: if price ratio of tokens changes from when you deposited, you're worse off than just holding.

```
IL formula:
  price_ratio = current_price / entry_price
  IL = 2 * sqrt(price_ratio) / (1 + price_ratio) - 1
  
  At 2x price change: IL ≈ -5.7%
  At 5x price change: IL ≈ -25.5%
  At 10x price change: IL ≈ -42.5%
```

**For quant**: LPs are essentially selling options. IL = the premium you pay for providing liquidity. Fee income = premium received.

## MEV: Miner/Maximal Extractable Value

One of the most important concepts for crypto quant.

**Definition**: profit that can be extracted by controlling transaction ordering within a block.

### How it works

Ethereum transactions sit in a **mempool** (public waiting area) before being included in a block. Block producers (validators/miners) choose which transactions to include and in what order.

Anyone who can see pending transactions can profit by inserting their own transactions in strategic positions.

### MEV Attack Types

**1. Front-running**
You see someone's large DEX trade in mempool → submit same trade with higher gas → get included first → price moves in your favor → victim gets worse price

**2. Sandwich Attack**
```
Step 1 (front-run): Buy token X (raises price)
Step 2: Victim's buy executes at inflated price
Step 3 (back-run): Sell token X (capture profit)
```

Your profit = victim's slippage (roughly).

**3. Arbitrage**
Price of ETH on Uniswap ≠ price on Sushiswap → atomically buy on cheap, sell on expensive in one transaction.

**4. Liquidation**
See undercollateralized loan in mempool → race to be first liquidator → claim liquidation bonus.

**5. JIT (Just-In-Time) Liquidity**
On Uniswap v3: see large swap → add concentrated liquidity in that price range → capture all fees → remove liquidity. All in same block.

### MEV Infrastructure

**Flashbots**: off-chain auction where searchers bid for block space without flooding mempool. Validators get extra revenue. Reduces gas wars.

**MEV-Boost**: middleware that lets validators outsource block building to specialized "builders" (who aggregate searcher bundles).

**Private mempools (RPC endpoints)**: services like Flashbots Protect route your transaction directly to miners, bypassing public mempool → can't be front-run.

### MEV as Quant Strategy

MEV searching is itself a quant strategy:
- Requires on-chain monitoring (custom node or subscription service)
- Sub-block latency competition
- Bot wars: if your bot is too slow, others extract before you
- Profit distributed across: liquidations (~$500M/year), arbitrage (~$200M/year), sandwich (~$300M/year)

## Layer 2 (L2) Scaling

Ethereum mainnet: ~15 TPS, $2-50 gas per transaction. Not viable for HFT.

Layer 2 = execution happens off-chain, security anchored to Ethereum mainnet.

### Rollup Types

**Optimistic Rollups**
- Assume transactions valid by default
- 7-day fraud proof window
- Examples: Arbitrum, Optimism, Base
- ~100-1000x cheaper than L1
- Fast finality for most apps

**ZK Rollups**
- Validity proof (zero-knowledge proof) submitted to L1
- Cryptographic guarantee of correctness
- No fraud window → faster L1 finality
- Examples: zkSync Era, StarkNet, Polygon zkEVM
- Computationally intensive to generate proofs

### L2 for Quant

| Chain | TPS | Fee range | Specialty |
|---|---|---|---|
| Arbitrum | ~40,000 | $0.01-0.10 | DeFi hub, Uniswap liquidity |
| Optimism | ~2,000 | $0.01-0.10 | Coinbase Base, OP stack |
| Base | ~10,000 | $0.001-0.05 | Coinbase backed, low fees |
| StarkNet | ~1,000 | $0.01-0.10 | Cairo/ZK, dYdX v4 |
| Solana | ~65,000 | $0.00025 | Highest speed, not L2 |

**For HFT on-chain**: Solana is the closest to viable. Sub-second finality, minimal fees. But centralization risks and outage history.

## Flash Loans

Borrow any amount, use it, repay it — all within one transaction. No collateral required. If you don't repay, the entire transaction reverts (as if it never happened).

```
Flash loan anatomy (one atomic transaction):
  1. Borrow 10,000 ETH from Aave (fee: 0.09% = 9 ETH)
  2. Use ETH to buy token on DEX A (price: $100)
  3. Sell token on DEX B (price: $105) → profit $500
  4. Repay 10,000 ETH + 9 ETH fee
  Net profit: $500 - $9 fee - gas = ~$450
```

Flash loans are used for:
- Arbitrage between DEXes
- Collateral swaps (in one tx: repay loan A, borrow from B)
- Liquidations (borrow to liquidate, use bonus to repay)
- Governance attacks (borrow voting tokens to pass proposal)

## Oracles

Smart contracts can't access off-chain data. Oracles bridge this gap.

**Chainlink**: dominant oracle. Network of nodes fetch real-world prices, aggregate off-chain, post to chain. Used by Aave, Compound, Synthetix.

**Uniswap TWAP Oracle**: on-chain price from Uniswap's own time-weighted average price. Manipulation-resistant but laggy.

**Pyth**: push-based oracle, sub-second updates. Used on Solana and L2s. Better for fast-moving prices.

**Oracle manipulation attacks**: if you can manipulate a DEX spot price used as oracle → exploit lending protocol. Led to ~$1B+ in exploits (Mango Markets 2022: $114M).

## Token Bridges

Move assets between chains. Send ETH from Ethereum to Arbitrum → bridge locks ETH on L1, mints "bridged ETH" on L2.

**Risk**: bridges are honeypots. Biggest crypto hacks:
- Ronin Bridge: $625M (2022)
- Wormhole: $320M (2022)
- Nomad: $190M (2022)

**For quant**: cross-chain arbitrage requires bridging. Bridge time (minutes to hours) and cost must be modeled.

## Wallets and RPC

**EOA wallet** interaction flow:
```
User → signs transaction → broadcasts to RPC node → mempool → block producer → chain
```

**RPC providers** (how you connect to blockchain):
- Infura (ConsenSys): most popular, free tier
- Alchemy: best developer tooling
- QuickNode: good performance, paid
- Self-hosted: geth/besu node — best for HFT (no rate limits, no latency)

**For HFT on-chain**: run your own node. Using shared RPC = shared latency, rate limits.
